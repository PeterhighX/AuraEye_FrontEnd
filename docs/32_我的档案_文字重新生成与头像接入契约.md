# 我的档案：文字重新生成与头像接入契约

日期：2026-10-27。状态：后端待实现、联调；本文新增接口是建议契约，不代表已经部署。

## 页面行为

- 顶部“开始分析”：使用已选择的原始照片进行面部分析，更新文字报告，并衔接透明头像生成。重新上传照片后走同一流程。
- 底部和菜单“重新分析”：只重新生成文字报告，不重新上传照片、不创建 face_analysis 任务、不生成或替换头像。
- 页面顶部用左侧动态图标、右侧文字的胶囊提示状态；同一状态显示 2 秒后消失，状态文字变化时重新弹出。提示消失不取消任务。
- 左侧透明头像尚未就绪时，使用居中的 72×72 占位图标；导航栏占位图标仍为 36×36。

## 已核验的后端能力与缺口

核验分支：`PeterhighX/AuraEye` 的 `codex/auraeye-backend-release-20261002`。

- `GET /v1/users/me/visual-profile` 返回当前档案、文字报告及头像状态。
- `POST /v1/users/me/portrait/generate` 接受 `request_id`、`profile_version`、`consent_version: "portrait-cutout-v1"`，返回 202 和 `portrait`、`poll_after_ms`。
- 当前头像服务要求源任务素材为 `demo_fixture`；普通账号真实照片不满足该条件，返回 503 `PORTRAIT_SOURCE_UNAVAILABLE`。前端保留这一能力边界，不把真实照片标记成演示素材。
- `ProfileNarrativeProcessor` 已能处理 `pending/running` 的文字报告，但尚无供客户端单独请求重新生成的路由。

前端当前已拆分按钮：底部入口提示“文字报告重新生成暂不可用”，不调用完整面部分析。后端部署下述接口后再接入；不得以重跑 face_analysis 作为替代方案。

## 建议新增文字专用接口

`POST /v1/users/me/visual-profile/narrative/generate`

请求头：Bearer JWT、`Content-Type: application/json`、`Idempotency-Key`（必须等于 `request_id`）。

```json
{
  "request_id": "req_narrative_0123456789",
  "profile_version": 3
}
```

约束：用户与租户仅取 JWT；正文只接受以上字段。`request_id` 沿用头像接口的标识规则。服务端从当前档案读取结构化快照及事实模板，客户端不上传照片或快照。

建议 HTTP 202 响应（沿用 API envelope）：

```json
{
  "request_id": "req_http_0123456789",
  "data": {
    "request_id": "req_narrative_0123456789",
    "profile_version": 3,
    "narrative_status": "pending",
    "poll_after_ms": 1500
  }
}
```

服务端原子占用本次生成请求，将当前档案的 `narrative_status` 更新为 `pending`，交给现有文字 Worker 处理。生成期间保留上次成功报告；同一账号、同一版本已有运行中任务时不得重复启动。

客户端按 `poll_after_ms` 轮询现有 `GET /v1/users/me/visual-profile`，以对应 `profile_version` 的 `narrative_status` 判定终态：

- `pending/running`：继续查询；重复轮询同一状态不重新显示胶囊。
- `completed`：新报告已保存，刷新文字；不改变头像、档案版本、源照片、结构化快照或上妆流程进度。
- `unavailable`：本次生成失败，保留旧报告。建议 GET 增加可空 `narrative_error: { code, message, retryable }`，用于区分失败原因。
- 档案版本变化：停止当前轮询并刷新档案，不把旧版本结果显示成新版本结果。

幂等：相同账号、相同 `request_id`、相同正文返回同一次任务，不重复执行或扣费；相同 ID 对应不同正文返回 409。用户明确发起新一轮文字生成时才创建新 ID。

建议错误继续使用 `application/problem+json`：

| HTTP | code | 含义 |
| --- | --- | --- |
| 401 | 沿用现有鉴权码 | 登录失效 |
| 409 | FACE_ANALYSIS_REQUIRED | 尚无可用的面部分析档案 |
| 409 | PROFILE_VERSION_STALE | 客户端档案版本已过期 |
| 409 | IDEMPOTENCY_CONFLICT | 同一请求 ID 对应不同正文 |
| 429 | 沿用现有限流码 | 请求过于频繁 |
| 503 | HERMES_UNAVAILABLE | 无法提交文字生成任务 |

## 真实照片透明头像支持

扩展现有 `portrait/generate` 服务以支持账号所属的真实源照片，复用既有上传及存储链路、租户隔离和授权校验；不得要求客户端伪造演示素材来源。源照片不可用时返回明确错误。生成仍复用当前 `profile_version`，结果需通过透明度校验，并继续通过已有受鉴权的图片接口读取。

后端完成后，前端移除 `canGeneratePortrait` 中仅允许演示素材的限制，所有受支持账号的顶部按钮即可完成文字与透明头像闭环。

## 联调验收

1. 顶部分析能更新文字及透明头像；真实照片与演示照片分别验证。
2. 底部重新分析只产生文字任务，头像 ID、源任务 ID、档案版本保持不变。
3. 重复提交不重复执行；跨账号不能读取或修改他人档案。
4. 文字生成失败保留旧报告，不以旧报告冒充本次成功结果。
5. 页面状态更新时弹出胶囊，2 秒无变化后隐藏，后台任务继续。
6. 无透明头像时左侧图标始终 72×72，不随 111×148 容器拉伸。
